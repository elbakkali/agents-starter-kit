# Product documentation

Non-technical docs for stakeholders, users, and product context. Keep these **up to date** when features ship or user-facing behavior changes.

## Index

| Document | Audience | Update when |
|----------|----------|-------------|
| [overview.md](overview.md) | Everyone — what the product is | Vision, positioning, or scope changes |
| [features.md](features.md) | PM, support, sales | Features added, changed, or removed |
| [user-flows.md](user-flows.md) | Design, QA, support | User journeys change |

## Rules for agents

- **Product** docs describe *what* the product does and *why* — no code snippets unless user-facing copy.
- **Technical** docs (API, architecture, setup) belong in [`../technical/`](../technical/).
- Update product docs when shipping user-visible features in the same PR.
